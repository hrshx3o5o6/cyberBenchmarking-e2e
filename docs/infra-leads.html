How we got here

  1. 30 Sep – 2 OctPilot on one task Claude Code on a Mac through a local metering proxy ("shim") with free models: none solved it. We proved the harness with a scripted oracle run (all four stages pass) and added dollar caps to the shim. First real result with glm-5.3-flash: patch-only solved. Moving to an x86 cloud VM cut the oracle run from 17.2 to 3.9 minutes.
  2. 3 – 13 OctSame five tasks, eight models Seven batches, each model run patch-only and end-to-end under the same limits ($10 and 90 minutes per run). Patch-only is close to saturated; end-to-end separates the models. We also found ways a run can look valid but not be (see below).
  3. 16 – 18 OctHarness comparison designed The shim gained an OpenAI Responses route so Codex can be compared with Claude Code. A GLM-5.3 comparison on four tasks ran; a larger three-model study is drafted but not run.
  4. 23 – 27 OctScaling on AWS Replica of the runner on EC2. Found that CPU, not memory, limits parallelism (8 to 10 slots comfortable on 16 vCPUs). Built and tested a two-VM Ray cluster. Kimi K3 end-to-end on 22 tasks: 11 passed, 8 stopped by spend caps.
  5. 29 – 31 OctAutoscaling and shared state A worker machine image, a Ray autoscaler on the existing head VM, a hosted Postgres that every task writes results and artifacts into, and a 30-task test of the whole path. Details below.
  6. 31 Oct – 1 NovNext study and the Qwen question The planned 100-task Qwen run hit a model-availability gap on Bedrock; a translation layer in the shim closes it. Details below.

What to read into it

  • Five tasks, one run per pair: a pattern to follow up, not a ranking.
  • nemotron-3-super mostly failed on malformed tool calls, not on the security task itself.
  • Validity checks we now run before any study: a bug file with a later modification time than the rest, a PoC without a patch (graded as no patch), a ground-truth PoC sitting inside the source archive, wording in build scripts that names the bug, and the endpoint's context-window limit.
  • Prompt-cache behaviour differs a lot between providers and moves cost by several times.

The cluster as it stands

Each task runs in its own containers behind a firewall; the shim meters every model call and enforces dollar caps. Workers do not keep results: a task is only finished once its results are read back from Postgres.

What it showed

  • Two workers launched within about 40 seconds and joined in about 2 minutes; tasks split evenly (10 per node).
  • Every result that reached Postgres had been read back successfully, which is the condition for shutting workers down.
  • 10 tasks never started because of a first-use race when several processes create the local state database at once. These were infrastructure, not task results. It was reproduced, fixed with a retry, and verified over 200 rounds.
  • Per-task cost came out higher than first estimated.

Qwen on Bedrock under Codex

The next study is 100 fixed e2e tasks with Qwen3.8-27B and Codex.

  • Gap: Qwen3.8-27B is not on Bedrock in any of 8 regions checked. The Bedrock Qwen models are all Qwen3-generation and serve only the Chat Completions format, while Codex speaks the Responses format.
  • Fix: a translation layer in the shim, off by default. 14 automated tests pass.
  • Real check: a three-turn streaming tool-call conversation passed on three Bedrock Qwen models for under $0.002 in total.
  • Caveat: they are stand-ins, older than the 3.8-27B, and the layer is our own code between the harness and the model.
  • Only one of the three reports cached tokens, so cache share can only be measured for that one.
